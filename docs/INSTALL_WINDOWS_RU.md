# SherloCAN v0.2.1 Alpha — установка Windows vehicle-test

## Назначение

Это сборка для первого контролируемого аппаратного испытания SherloCAN с J2534/OpenPort 2.0. Software CI проверяет frontend, backend, тесты и установку используемой J2534 Python-библиотеки. Реальная работа конкретного OpenPort, его DLL и CAN-шины автомобиля считается подтверждённой только после фактического hardware acceptance.

## Поддерживаемая ОС

Основная целевая система: Windows 10/11. Windows 8.0 не заявляется как поддерживаемая. Совместимость с Windows 8.1 не является критерием этой vehicle-test сборки.

## Что установить заранее

1. Python 3.12.
2. Официальный драйвер Tactrix OpenPort 2.0 / J2534.
3. Распаковать релиз полностью, например в `C:\SherloCAN`.

Node.js на тестовом ноутбуке не нужен: frontend уже собран в CI.

## Установка SherloCAN

В корне распакованного релиза запустите:

```bat
scripts\setup_windows.bat
```

Сборка содержит каталог `vendor\` с проверенными wheel-пакетами, поэтому установка Python-зависимостей выполняется локально без обращения к PyPI.

После установки запустите:

```bat
scripts\run_release.bat
```

Откройте:

```text
http://127.0.0.1:8000
```

## Если DLL OpenPort имеет другую разрядность

SherloCAN проверяет архитектуру зарегистрированной J2534 DLL. Если UI сообщает несовместимость DLL и текущего Python-процесса, не обходите проверку.

Для 32-битной DLL установите Python 3.12 x86 и пересоздайте окружение:

```bat
rmdir /s /q .venv
scripts\setup_windows.bat x86
```

После этого снова запустите `scripts\run_release.bat`.

Это не означает, что любая OpenPort DLL обязательно 32-битная: используйте фактический результат проверки архитектуры на вашем компьютере.

## Проверка до автомобиля

- UI открывается;
- `/health` отвечает;
- synthetic demo явно обозначен как synthetic;
- J2534 Provider/DLL обнаруживаются либо корректно показывают ошибку;
- Device Open и CAN Channel не считаются пройденными без соответствующего теста;
- bitrate остаётся UNKNOWN, пока диагност не введёт подтверждённое значение.

## Первый аппаратный тест

Идите только последовательно:

1. Provider/DLL.
2. Device Open.
3. CAN Channel — только с подтверждённым bitrate.
4. Короткий bounded capture.
5. Capture Acceptance.

К capture нельзя относиться как к пригодному evidence, если `frames_observed = 0`, есть DATA LOSS, отсутствуют RAW/SHA-256 либо cleanup не завершён корректно.

## Ограничения

Эта сборка не обещает:
- автоматическое определение bitrate;
- ECU↔CAN-ID mapping;
- автоматический root cause;
- электрическую пассивность J2534-адаптера;
- подтверждённую работу конкретного OpenPort до реального теста.

Приложение не содержит намеренного пути передачи CAN-сообщений в vehicle-test capture.
